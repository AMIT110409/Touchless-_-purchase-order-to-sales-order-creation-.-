Process Flow

Step-by-Step Workflow

How a Purchase Order travels from customer email to SAP Sales Order — every actor, decision, and handoff explained.

⬤ Phase 1 — Trigger / Ingestion
1
📧 SO Email Inbox Happy Path

Customer Sends PO via Email

Customer sends a Purchase Order in any format (PDF, scanned image, Excel) to salesorders@envalior.com.

InputRaw Email + PDF attachment
OutputEmail arrives in SO Email Inbox
2
⚙️ MS Graph API Happy Path

Graph API Pulls Emails + Archives to Azure Blob

The AI agent uses MSAL Client Credentials to poll the SO inbox via Microsoft Graph API. Emails are pulled, attachments extracted, and raw POs are archived to Azure Blob Storage for auditability. The script graph_email_handler.py handles this.

InputUnread emails from SO Inbox
OutputRaw Email + PDF saved locally + uploaded to Azure Blob
Microsoft Graph API MSAL Auth Azure Blob Storage
⬤ Phase 2 — OCR & AI Extraction
3
🔍 PaddleOCR Happy Path

PaddleOCR Extracts Raw Text from PO Document

PaddleOCR v2.8 (GPU-accelerated) performs optical character recognition on scanned/image PDFs. For native digital PDFs, PyMuPDF extracts text directly. Output is raw multi-language text ready for LLM processing.

InputPDF / Image → Raw Text
OutputOCR Text + JSON metadata
PaddleOCR v2.8 PyMuPDF GPU CUDA
4
🤖 Claude Sonnet LLM Happy Path

Claude Sonnet LLM Extracts Structured JSON

Claude Sonnet (via Anthropic API) processes the raw OCR text and performs multilingual JSON extraction — pulling Customer name, PO number, dates, quantities, material codes, and delivery addresses. Cross-language resolution handles terms like Niederweisen → VF, Verpackungen, 高仕 → Molex Shanghai.

InputOCR Text + JSON
OutputEnriched JSON → results_*.jsonl
Claude Sonnet (Anthropic) claude_client.py Multilingual NLP
⬤ Phase 3 — KB Enrichment
5
🔗 Customer Alias Engine Happy Path

Customer Alias Resolution + Fuzzy Match

The CUSTOMER_ALIASES dictionary performs cross-language resolution (e.g., Niederweisen → VF, 高仕 → Molex Shanghai). If no exact match is found, the Fuzzy Match Engine (difflib SequenceMatcher, threshold > 0.3) resolves Sold-To & Ship-To IDs from the Knowledge Base (SQLite · SAP KNA1, KNVP, KNMT).

InputStructured JSON (raw customer name)
OutputEnriched JSON (resolved SAP Sold-To / Ship-To IDs)
CUSTOMER_ALIASES SequenceMatcher SQLite KB (52K+ vendors)
⬤ Phase 4 — Material Mapping
6
📊 Material Cross-Ref Happy Path

Excel Mapping + Material Cross-Reference + SO Grouping

The Excel Mapping File provides business-managed rules for Sales Org, Order Type, and Material. The Material Cross-Ref engine (sales_order_mapper.py) performs case-insensitive, startsWith, and reverse-prefix matching to convert customer material codes → internal SAP material numbers. SO Grouping (Rule X or O) determines how line items are grouped into Sales Orders.

InputEnriched JSON + Customer material codes
OutputMapped Sales Orders (SAP material codes + SO groups)
Excel Mapping File sales_order_mapper.py SO Grouping (X/O)
⚡

Decision: Validation Passed?

✅ YES — All data resolved Sends validated payload to Celonis → continues to Phase 5
❌ NO — AI Failure / missing mapping Routes PO to Regional CS Exception Queue → Phase 7
⬤ Phase 5 — Celonis Validation
7
✅ Celonis Validation + Action Flow Happy Path

Celonis Validates + Triggers SO Creation in SAP

AI posts the validated payload to PO_EXTRACTION_RESULTS via Pycelonis SDK (push_to_celonis.py). Celonis applies business rule validation (customer, material, delivery, order type). If all rules pass, the Celonis Action Flow triggers a Webhook that posts the SO payload to SAP EPP for Sales Order creation.

InputValidated payload → PO_EXTRACTION_RESULTS
OutputSAP Sales Order created (SO_DOCUMENT_INSERT_API)
Celonis EMS Pycelonis SDK Action Flow (Webhook)
⬤ Phase 6 — Output & Action
8
🗄️ SAP EPP Happy Path

SAP EPP Creates Sales Order

SAP EPP receives the SO payload via SO_DOCUMENT_INSERT_API and creates the Sales Order. The original PO is archived on the specific SO record for full traceability.

InputSO payload from Celonis Action Flow
OutputSAP SO Created
9
📎 Robona Happy Path

Robona Attaches Original Email to SAP SO

Robona pulls the original customer email (EML/MSG) and attaches it directly to the SAP Sales Order record, ensuring full auditability.

InputOriginal email + SAP SO number
OutputEmail archived on SAP SO record
10
✅ Confirmed Happy Path

SO Confirmation Sent to Customer

SAP Output Determination auto-emails the Sales Order Confirmation to the customer. Requires middleware config. Touchless cycle complete. ✅

⬤ Phase 7 — Exception Handling
E1
⚠️ AI Failure Exception Path

AI Failure → Routes to Regional CS Inbox

When the AI encounters an OCR failure, unknown customer, or unmapped material, it auto-forwards the PO + error reason to the Regional CS Inbox via Graph API, routed by SAP ER mapping (EMEA, APAC, or AMS).

InputError + original PO
OutputPO forwarded to Regional CS Exception Queue
E2
👥 CS Manual Handling Exception Path

CS Team Reviews + Fixes or Replies to Customer

Regional CS team picks up unprocessable PO. If fixable, they fix & re-submit to SO inbox. If not fixable, they reply to customer requesting a corrected PO.

InputError + original PO in CS inbox
OutputFixed PO re-submitted or customer notified
E3
🔄 Feedback Loop Retrain Loop

Corrections Update KB — Aliases Auto-Improve

Manual corrections from CS are fed back to the Knowledge Base. Customer aliases and material mappings auto-improve, ensuring the same PO type is processed touchlessly next time.

Feedback Loop KB Auto-Update Alias Improvement
